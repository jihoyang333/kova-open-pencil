Toasts & snackbars · B1.1–B1.6

One floating-element pattern that every CRUD action in Kova reaches for. Five variants (success · error · info · action · AI), anchored bottom-right per the design.md §3.12 floating-element convention. Stack ordering is oldest-bottom; the newest toast appears at the top of the visible cluster. Errors are sticky and carry an inline retry; everything else auto-dismisses. Two edge cases shown: long-content wrap and z-order over an open dialog. Round-1 cleanup: all backdrop chrome is now LIFTED verbatim from A7 + A6+A2a (no more reconstruction); modal-backdrop rgba corrected to post-rewire --bg; canvas-context scenes scoped down to a dim plate per Q1.

FILE B1 · §2 · B1.6 Stack of 3

B1.6 · Stack ordering — newest on top, oldest at bottom

When toasts arrive faster than they dismiss, they stack with the newest at the top of the cluster and the oldest closest to the corner. Inter-toast gap is 8px. Stack growth is upward; the bottom edge stays anchored at bottom: 22px. Each toast retains its own dismiss/auto-dismiss timer independently.

FILE B1 · §2 · Edge case · long content

Long content — wrap, never truncate

When the message overflows the 280-px minimum, the toast grows vertically until it hits the 420-px maximum width, then wraps. Truncation with ellipsis is rejected — toasts already have to compete for attention; hiding text behind "…" wastes the impression.

FILE B1 · §2 · Edge case · toast over open dialog

Z-order — toast wins over modal scrim

If a toast fires while a dialog is open (e.g. an autosave fires while the user is in a Snapshot dialog), the toast renders above the modal backdrop and the dialog itself. The dialog is the user's current task; the toast is a peripheral system event — it must not be hidden by the modal, and it must not require the user to dismiss the dialog to acknowledge. Backdrop scoped down per round-1 Q1; the dialog itself is real .dlg chrome lifted from A6+A2a.

  • Why above the dialog and not below. A toast is a system-level interrupt; a dialog is a user-driven task. Hiding the toast under the modal would require the user to finish the modal before learning about the system event — which can include errors that make the modal's outcome wrong.

Behavior commitments

  • Auto-dismiss windows: success 4s · info 3s · action 5s · AI 8s · error sticky.
  • Hover pauses dismissal. Standard floating-element behavior — survives multi-toast read-time.
  • Keyboard: Esc dismisses the most-recent toast. Tab cycles through inline action buttons in DOM order.
  • Z-order: toast 20 · modal 10 · backdrop 5. Toast wins over every other floating surface except the command palette (which captures input).
  • Stack cap: design suggests ≤3 simultaneous; implementation drops oldest off-stack (kept in notification history). Cap value is a code-time choice.
