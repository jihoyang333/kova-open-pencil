  • Toast pattern is byte-identical to B1.1. Same .toast-stack position (bottom-right, 22px from edges). Same .toast.success chrome. Same check lead glyph in --ink-2. Same auto-dismiss 4s commitment from B1's behavior block.
  • Inline result + toast both fire. The inline result is the persistent state on the surface; the toast is the moment-of-event reinforcement that vanishes after 4s. Two surfaces, same content, complementary scopes — the same pattern as the autosave pill + autosave toast in B1.3.
  • Why both. If the user navigated away mid-upload, only the toast tells them it landed. If they're still on the surface, the inline row tells them where the file lives now. Belt-and-braces with low pixel cost.
Coherence notes — what this file commits to

What B8 commits to

New layout-only classes

  • .upl-zone — drop zone (2px dashed border = explicit allowed exception to design.md §5 ban 6).
  • .upl-ring-wrap · .upl-ring-svg · .upl-ring-track · .upl-ring-fill · .upl-ring-cancel — circular progress around avatar.
  • .upl-bar-panel · .upl-bar-track · .upl-bar-fill — horizontal progress in a list-row anatomy.
  • .upl-result · .upl-result.error — terminal-state inline rows.
  • .upl-list · .upl-list-row · .upl-list-row .status.success/.in-progress/.error/.queued · .upl-list-row .row-prog — multi-state file list.
  • .scene-grid · .scene-card — review-page catalog only for B8.2–B8.6; not shipped.

Tokens used (none new)

  • Surface: --bg · --page · --rail · --fill · --fill-2
  • Ink: --ink · --ink-2 · --ink-3
  • Lines: --line · --line-2
  • Accent (progress fill, browse link, success check): --accent
  • Warn (error variant): --warn · --warn-edge — degraded ramp per design.md §1.1.

Behavior commitments

  • Drop-zone hover lifts background to --fill + border to --ink-3. Drag-over should lift border to --accent + tint background --accent-soft (out of scope for static mock; same vocabulary as canonical input :focus state).
  • Progress ring is SVG-driven; stroke-dashoffset animates from 207 (0%) to 0 (100%). Stroke-linecap round.
  • Progress bar uses width transition at 200ms ease-out. Indeterminate state (out of scope) would loop a 30%-wide segment with translateX, mirroring B7 skeleton's gradient.
  • Cancel × is universal — same affordance on ring, bar, list-row. Aborts upload; queued rows clear immediately.
  • Error state stays sticky until user clicks remove or retry. No auto-dismiss. Same rule as B1.2 sticky error toast.
  • Toast (B8.8) auto-dismiss 4s per B1.1 commitment. Inline result row is persistent.

Dashed 2px exception (B8.1) — explicit log

  • design.md §5 ban 6 says no 2px borders on chrome. Dashed reads as a different visual class than solid 2px (the actual ban target — "thick lines around boxes").
  • Drop-zone affordance has a long-standing dashed treatment across web platforms; switching to 1px hairline would lose the "drop here" semantic.
  • Existing precedents in the codebase: A2+A3 .bp-newcard uses 1px dashed; A2+A3 .onb-drop uses 1px dashed; A7 .empty-pane uses 1px dashed. B8 .upl-zone upgrades to 2px dashed for the active drop affordance — slightly stronger pull on a high-affordance surface, while the 1px dashed precedents remain for quieter empty-state contexts.
  • If the founder prefers strict 1px dashed for parity with A11/A2, the change is a single property update. Flagged as ambiguity — defaulting to 2px dashed because of the literal brief recommendation in §3.5 / §6.2; awaiting confirmation.
