  • Cross-fade, not slide. 200 ms ease-out is the canonical Material/iOS shorthand — long enough to read as a transition (not a snap), short enough not to feel slow. Sliding would create motion that competes with the user's eye landing on the now-real content; cross-fade is invisible.
  • No layout shift because skeleton chrome and populated chrome share the same dimensions. The skeleton circle is 32 × 32; the populated avatar is 32 × 32. The skeleton lines are 13 px tall; the populated text-line is 13 px tall (font-size 13 + line-height 1.55 = 20 px box, but the text baseline lands at 13 px from top — it overlaps the same skeleton bar perfectly).
  • Reduce-motion fallback swaps skeleton → populated with no transition (instant). Same content, same layout, just no animation.
Coherence notes — what this file commits to

What B7 commits to

New layout-only classes

  • .skeleton — single new component family. .skeleton::before animates a moving gradient (--fill → --fill-2 → --fill) at 1.4s ease-in-out infinite. Scoped exception to design.md §5 ban 5 (no gradients on chrome) — see delivery notes.
  • .skeleton.r-pill / .r-card / .r-line / .r-circle — corner-radius variants matching populated counterparts.
  • .scene-grid · .scene-card · .scene-card .sc-head/.sc-body — review-page catalog only for B7.4; not shipped.
  • .fade-demo · .fade-demo .panel · .fade-demo .arrow — annotation-only spec for B7.5; not shipped.

Tokens used (none new)

  • Surface: --bg · --page · --rail · --fill · --fill-2
  • Ink: --ink · --ink-2 · --ink-3
  • Lines: --line · --line-2
  • Accent (only on canonical .nav.active / .it.active tints): --accent-soft via canonical CSS — not redeclared.
  • The brief's named tokens (--color-surface-input, --color-surface-input-hi) don't exist in canonical kova-hifi.css; canonical exposes the same values as --fill / --fill-2. Used canonical names.

Behavior commitments

  • Animation duration: 1.4s ease-in-out infinite. Slow enough not to flicker, fast enough to read as alive.
  • Gradient sweep width = 50% of parent; translateX(-100%) → translateX(300%) across the cycle.
  • Reduce-motion fallback: animation disabled, static --fill-2 fill applied. @media (prefers-reduced-motion: reduce).
  • Fade-out transition: 200ms ease-out cross-fade when content lands. No layout shift because skeleton chrome mirrors populated chrome 1:1.
  • Skeleton chrome does NOT shimmer where the data is already known synchronously — sidebar nav active, topbar online pill, breadcrumb, page h1, sub-nav active state. Only fetched payloads shimmer.

Out of scope

  • Page-level "Loading…" indicator for total cold starts (route splitting). Not designed here; recommend a centered .skeleton at viewport-center if needed pre-route-resolve.
  • Streaming AI generations — the canvas right-rail AI panel handles those (per B1.5 AI-toast notes); not skeleton work.
  • Progress bars for known-percent operations — that's B8 upload UI, not skeleton.
