FILE B2 · §1 · B2.3 · Network unreachable

B2.3 · Can't reach Kova

App-level network failure (no DNS, no TLS handshake, server unreachable). Distinct from A13's in-chrome offline strip — A13 says "I noticed your machine is offline"; this page says "I can't get to the server even though your machine appears online". Renders without sidebar/topbar so it works pre-auth (a sign-in attempt that times out hits this page, not A13).

Network down · pre- and post-auth surface (no sidebar/topbar)
B2.3 · hi-fi

Can't reach Kova

Check your internet connection. If you're working in a canvas, recent changes are saved locally and will sync as soon as you're back online. If you're trying to sign in, retry once you have a connection.

Retry connection
  • Pre- vs post-auth. Renders without sidebar or topbar so it works before the user is signed in (sign-in network failure) and after (logged-in network failure during canvas edit). Symmetry beats split surfaces here — the page tells the user the same truth in both cases.
  • Single CTA: Retry. No "Continue offline" — the page replaces chrome whenever the server is unreachable, and there's nothing for the user to interact with offline at that point. Local Yjs autosave still runs in the background; once the connection is restored and the user retries, their queued edits sync.
  • Why distinct from A13. A13 is in-chrome (sidebar pill + banner) for graceful degradation while the user keeps working; B2.3 is the page-replacing fault for catastrophic loss of server reachability. Different scope, different surface.
Coherence notes — what this file commits to

What B2 commits to

New layout-only classes

  • .err-page — full-viewport flex-center wrapper. No sidebar / topbar.
  • .err-card — focal card, 420 × content. No outer hairline.
  • .err-icon-tile — 48×48 icon tile, invisible (bg = --bg, no border) so the glyph reads as floating directly on the page. Icon glyph in --ink-3 stays visible.
  • .err-cta-stack — primary on top, text-button below.

Tokens used (none new)

  • Surface: --bg · --page · --rail · --fill
  • Ink: --ink · --ink-2 · --ink-3
  • Lines: --line · --line-2
  • No accent. No warn. The status palette deferral (design.md §5 ban 12) applies — fault role is communicated through glyph + copy, not color.

Scope split with A13 (offline)

  • A13 = graceful degradation. User's machine is offline; the app stays loaded; sidebar pill + banner indicate status; canvas edits queue locally.
  • B2.3 = catastrophic unreachability. The app cannot talk to the server at all — possibly because we're down, possibly because the user is offline before any session loaded. Page replaces chrome.
  • Detection rules (for the implementer): if navigator.onLine === false AND a session was already established → A13. If a network request fails AND no session yet OR an active session can't reach the server → B2.3. The two surfaces never render simultaneously.

Deferred / out of scope

  • 403 / 401 surfaces. Permission denied + session expired need their own pages — out of scope for this round. Recommend they reuse .err-card with different glyphs (shield-off, log-out) and copy.
  • Maintenance / deploy-window page. Separate from 500 because it's planned, not faulted. Out of scope.
  • Status palette themed re-render. Once design.md §1.1 ships --color-status-error etc., the icon-tile + foot-meta should re-theme to the warn variant. No markup change — token swap only.
