  • Tone is warm + slightly self-aware, not apologetic or technical. "We'll be on mobile eventually — for now, the canvas needs more screen real estate than phones can offer" frames the limitation as a deliberate trade-off, not a missing feature. Reads like a real designer talking, not a fault page.
  • Mailto handoff is the primary CTA. Most users on mobile won't switch immediately — sending themselves the desktop URL by email is the friction-free way to remember "open this later on the laptop." Subject + body prefilled per handoff §7.2.
  • Secondary is "Learn more," not "Try anyway." Letting users push through to a broken canvas would make the whole product feel half-built; redirecting to the marketing site keeps the surface honest.
  • Foot link "Reload the page" covers the desktop-on-narrow-window case — a desktop user who happened to drag their browser narrow enough to trigger the breakpoint. Less common but worth covering.
  • Mobile breakpoint at 639px. Below this width: full-bleed card (no border, no shadow, page padding only). At 640–1023px: 440px card (tablet portrait). At ≥1024px: 480px card (full desktop). All three viewports tested via Playwright shoots.

B6.2 · Almost — bigger screen needed · tablet edge

Edge case for users on portrait iPad (768px) or other "almost-but-not-quite" viewports. Same chrome as B6.1 but reframed copy: "Almost — Kova needs a slightly bigger screen. Try a laptop or rotate your tablet." Acknowledges the user is closer than a phone-sized visitor without granting access. Designer call kept this as a separate scene because the tablet copy genuinely differs — copying B6.1's "phones can offer" language to an iPad would feel wrong.

Coherence notes — what this file commits to

Patterns this file inherits and decisions a future code-agent needs to wire.

Coherence audit
B6 · notes
  • Theme isolation. Light only — root <html> carries no dark-mode attribute, no dark-mode tokens referenced. Mobile fallback is pre-auth chrome.
  • Auth-card chrome lifted from A15 per handoff §3.8 LIFT protocol. The lifted block is unmodified.
  • Two extension classes: (a) .auth-icon + .auth-icon.dim for the 24×24 icon (same shape as B5's, redeclared locally — files don't cross-import); (b) .auth-card.mobile-fallback for the wider 480px desktop variant + responsive bleed at <640.
  • Three breakpoints, three chrome variants. ≥1024 = 480px card with border + shadow (desktop); 640–1023 = 440px card (tablet edge); <640 = full-bleed (no border, no shadow, edge padding only). Verified at 375 + 1440 via Playwright; tablet 768 captured by intermediate inference.
  • Page meta-viewport differs from Batch A. Other Batch A files use <meta viewport="width=1440"> (preview-poster convention). B6 must render correctly at mobile widths, so it uses width=device-width, initial-scale=1. The doc-poster section.block / .screen wrappers still render correctly on the review page; only the actual scene content is responsive.
  • Mailto prefill per handoff §7.2: subject "Open Kova on desktop", body "Click this link from your laptop: https://app.kova.io". URL flagged for replacement when production domain is final.
  • Open wiring questions (flag for engineering): (a) Does the breakpoint router live at the SPA layer (Vue Router guard) or upstream (Cloudflare-side redirect)? Recommend SPA — keeps the "Reload the page" foot link working without server roundtrip; (b) Should B6.2's "I'll rotate my tablet" secondary auto-listen for orientation change and reload, or stay no-op? Recommend listen + reload for friendly UX; (c) Marketing-site URL for the "Learn more" secondary — confirm with the founder before final wiring.
