  • Single CTA — sign in. No secondary because the recovery is symmetrical: every cause routes through /login. Reducing the surface keeps the user on the path.

FILE B4 · NOTES

Coherence notes — what this file commits to

Patterns this file inherits and decisions a future code-agent needs to wire.

Coherence audit
B4 · notes
  • Theme isolation. Light only — root <html> carries no dark-mode attribute, no dark-mode tokens referenced. The companion B4.7 lives separately in batch-a-additions/dark/.
  • Auth-card chrome lifted from A15 per handoff §3.8 LIFT protocol. The A15 inline <style> block was reproduced byte-for-byte — see source batch-a/light/Kova Hi-Fi A15 Auth - Light.html lines 33–270.
  • Two extension classes only: .auth-field .input.error + .auth-otp .cell.error (warn edge), plus .auth-otp.locked for the dim-cells variant and .auth-field .help .accent-link for the inline accent-link in meta. All append below the lifted block; the lifted block is unmodified.
  • Status palette deferred per design.md §5 ban 12. --warn currently degrades to --ink-2 in light. When the palette ships, every .error-tinted edge re-themes to red without markup change.
  • Inline accent-link uses var(--accent) directly per handoff §5.3. This is deliberately a hard reference (not via --accent indirection) inside the .help meta — keeps the visual treatment of "one accent word in a warn sentence" consistent regardless of what --warn resolves to.
  • OTP cells. 44×52 lifted from A15; the locked state uses dim dots (·) instead of empty cells to differentiate "paused" from "awaiting input". Wiring decision: 15-minute lockout is informational (no live timer) — match Supabase rate-limit behaviour. Server makes the unlock decision when the user retries.
  • Primary-CTA enabled-state preserved. B4.3, B4.5, B4.6 all keep the primary clickable. Disabled buttons in error states make recoverable failures feel punitive; the server should re-decide on retry.
  • Open wiring questions (flag for engineering): (a) Does B4.6 risk account enumeration in production? Founder call to pivot to "If this email is registered…" or stay; (b) Is the 5-attempt lockout in B4.4 a Supabase setting or app-side gate? (c) Does B4.1 expire on first click or on first decrypt? (Magic-link convention is the latter.)
